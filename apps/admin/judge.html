Section 02

Risk intelligence

Every transfer is scored before funds move. Scoring combines deterministic rules with an ML anomaly-detection model, and the resulting band decides what happens next.

Risk AI service —
Open risk cases —

Scoring model · Rules + ML anomaly detection

This is a scoring service, not an autonomous agent: it evaluates a request it is given and returns a band. It takes no action on its own. Case count is read from the live risk case list; no scoring request is submitted from this page.

Decision bands

ALLOW Normal transfer — proceeds without interruption
STEP-UP Extra verification required before funds move
BLOCK Transaction stopped — no money leaves the account

Section 06

Security engineering

Technical evidence, labelled honestly. These are capabilities present in the codebase at competition scale — not a claim that every control is enforced in a production deployment.

Implemented capability
DPoP-capable security implementation
Proof-of-possession token binding is implemented and configurable per service; it is not enforced for every route in the demo profile.
Implemented capability
Post-quantum cryptography
Lattice-based signature scheme used for ledger anchor signing, in place of a classical-only signature path.
Implemented capability
Shamir 3-of-5 secret sharing
Real threshold secret sharing over a finite field, with a quorum-gated reconstruction path. See the vault section above.
Implemented capability
Tamper-evident ledger
Hash-chained journal entries with verifiable proofs, so a retrospective edit is detectable rather than silent.
Implemented capability
Service-oriented isolation
Independently deployed services, each owning its own logical database and exposing state only through its API.
Implemented capability
Prometheus / Grafana / Loki observability
Metrics, dashboards and log aggregation across the stack, including per-service request histograms.
Demo-scale implementation
Enclave & custody ceremony
The ceremony workflow and egress discipline are modelled in software. This is not a hardware security module and not a real confidential-computing enclave.
Demo-scale implementation
Payment scheme connectivity
Scheme adapters and ISO 20022 message generation are simulated. No live scheme, card network or central-bank connectivity exists in this build.

Explicitly not claimed: Kubernetes orchestration, an API gateway product, service-mesh based quarantine enforcement, a production HSM, a real hardware enclave, mutual-TLS between services, or real Visa / LankaPay connectivity.

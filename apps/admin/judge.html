Enterprise capabilities

What makes this a fabric, not an app

Ten services, four languages, one contract discipline. The properties below are architectural commitments, not features toggled per deployment.

Polyglot service mesh

Kotlin core for the money-moving domain, Go for the payment rails, Python for risk models, Node for messaging. Each language sits where it earns its keep.

Saga orchestration

Transfers run as compensating sagas across account, ledger and risk. A partial failure unwinds deterministically instead of leaving torn state.

Database per service

No shared schema, no cross-service joins. A compromised service reaches its own PostgreSQL instance and nothing else.

Tamper-evident ledger

Append-only hash chain, Merkle-anchored and signed on a fixed cadence. Any retroactive edit breaks verification publicly.

Offline-first inclusion

Signed offline vouchers, a sub-50 KB low-data page, and USSD *334# for feature phones. Connectivity is a preference, not a requirement.

Post-quantum ready

ML-KEM-768 key encapsulation and ML-DSA-65 signatures on the trust anchor, chosen against a long-horizon threat model.

Idempotent write path

Every state-changing call carries an idempotency key, so a retried transfer settles once regardless of network behaviour.

Uniform observability

Micrometer-shaped Prometheus metrics from every runtime — JVM, Go and Node alike — so one dashboard query covers the whole mesh.
